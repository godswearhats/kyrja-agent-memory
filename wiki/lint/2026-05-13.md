load-bearing citation is the deep-dive in `_archive/atomized-2026-05-12/`.
The deep-dive is a Kyrja-internal synthesis, ingested-from, but not
promoted to a `source/*` page. Yesterday's report flagged this prospectively
("Deep-dive atomization gap"); today's lint shows the gap dominates the
unsourced-claim count.

**Proposed resolution** (one of):
- (a) Promote `agentic-memory-scaling-deep-dive.md` to
  `source/agentic-memory-scaling-deep-dive.md` (or split by section), so
  Rule 3 finds it via the path whitelist;
- (b) Extend Rule 3's whitelist to include `_archive/atomized-*/` paths —
  acknowledges that ingested material counts as a source even after archival;
- (c) Both.

Per evidence-anchoring discipline ([feedback_epistemic_lens]), (b) alone
risks letting internal synthesis hide as external evidence. (a) is the
cleaner long-term move but requires real work. (b) as a stopgap while (a)
is queued seems pragmatic.

**Recommend AJ-conversation before changing the rule.**

### Rule 7: 60%+ false-positive rate sustained

Yesterday's narrowing helped but didn't catch up with the new content
shapes:

- Vendor-reported magnitude prose on incumbent pages ("117× token
  reduction", "300× memory footprint", "+25% / +314% F1") — these are
  attributable to vendor claims via same-bullet link but Rule 7 doesn't
  see them as tagged.
- Bullet-label quantities (`**Token usage reduced 117x**; …`) — the
  bold-marker prefix may be defeating the procedural-whitelist position

**Proposed v0.4 fix**: either (a) suppress Rule 7 inside the same bullet
window as a recognised citation link (parallel to Rule 3's relaxation),
or (b) demote Rule 7 warnings to info-severity by default and surface
only on opt-in deep audit. Aligns with the sustainability calibration in
yesterday's report.

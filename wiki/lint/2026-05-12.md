## Drift to flag (for SCHEMA v0.4 discussion)

### Rule 3 too narrow — citation-target whitelist

The current rule looks only for `source/*` or `experiment/*` links in
the same-bullet window. False-negatives observed:

1. **Sibling experiment-file references.** From `experiment/foo/exp1.md`,
   linking to `./README.md` (the umbrella in the same folder) doesn't
   contain `experiment/` in the path string. The link IS an
   experiment-page citation but the regex misses it.
   Affected: experiment/.../exp1-task2.md:44, exp2-task3-c-replication.md:35.
2. **Concept-page citations for [ASSERTED] claims about wiki-defined
   products.** When an open-question cites the cascading-failures
   *concept* page (our own synthesis), rule 3 still demands a `source/*`
   link. But the cascade IS a wiki-defined product — the concept page is
   the canonical citation.
   Affected: open-question/multiplicativity-vs-overlap.md:13.
3. **Experiment pages as self-sources.** Pages inside `experiment/foo/`
   that report their own measurements can't cite themselves.
   Affected: README.md:29, 39, 43.

**Proposed v0.4 fix**: expand citation targets to (a) sibling files in
the same `experiment/` folder, (b) concept pages for `[ASSERTED]` claims
on wiki-defined products, (c) treat the page-as-self-source for measurement
results on the experiment page where the measurement lives.

### Rule 8 lookahead-only — misses preceding construct-validity notes

Current implementation looks 400 chars AFTER each `[MEASURED]` tag. Real
patterns missed:

1. **Construct-validity in section header.** experiment/.../README.md has
   a `## Construct-validity note (load-bearing)` section that applies to
   all `[MEASURED]` tags later in the page. The 400-char-after window
   doesn't see the section header.
2. **Construct-validity in preceding bullet.** decision/precision-over-recall.md
   has the −50% bullet with full construct-validity note; the +50% bullet
   below references it implicitly.

**Proposed v0.4 fix**: look ±400 chars (both directions), OR detect a
preceding `Construct-validity` section/header within the page and exempt
`[MEASURED]` tags below it.

### Rule 7 false-positive rate high on procedural metadata

~32 of 44 untagged-claim findings are sample sizes, costs, durations,
dates, version numbers. The quantitative-pattern regex doesn't
discriminate "X% of users" (empirical) from "n=4 per variant"
(methodology).

**Proposed v0.4 fix**: add whitelist patterns that pre-filter common
procedural shapes:
- `\bn\s*=\s*\d+\b` when followed by "per", "trials", "sessions"
- `~\$\d+,?\s*\d+\s*trials` (cost-trial methodology summaries)
- `~\d+\s*min` (durations)
- ISO dates (`\d{4}-\d{2}-\d{2}`)
